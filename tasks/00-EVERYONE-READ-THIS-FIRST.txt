WHAT WE ARE BUILDING
--------------------
A website where students of our school can post their apartment in
Milan, Madrid, Geneva, Paris or Marseille, so another student can take
it over when they move campus. Other students browse the listings,
open one, and contact the person who posted it.

Taoufik owns the "backend" (database, login system, API, deployment).
You own a piece of the "frontend" (the pages people see). Your personal
file in this folder tells you exactly what to build.

You do NOT need to understand the whole project. You only need to
understand your page(s) and the shared "Listing" shape below.


TOOLS YOU NEED (install once)

2. Node.js (LTS)  https://nodejs.org           -> check with:  node -v

STEP 0 — GET THE CODE  (do this once)
--------------------------------------
   git clone https://github.com/ASRIDK/student-housing-marketplace.git
   cd student-housing-marketplace
   git checkout <your-branch>  # your branch name is in your task file
   git merge main              # pull in the latest skeleton from Taoufik
   npm install

You should see the site with 9 apartments coming from the shared
database. If not, ask Taoufik before going further. Node 22+ needed.

Before every pull request, run these four and fix anything red:
   npm run lint
   npm run typecheck
   npm test
   npm run build

PROJECT STRUCTURE
-----------------------------------------------------
   src/app/               -> pages. Each folder = a URL.
   src/app/page.tsx       -> the home page  ("/")
   src/app/layout.tsx     -> wraps every page (navbar, footer) - Andrea
   src/app/listings/[id]/page.tsx -> one listing  ("/listings/123") - Leo
   src/app/listings/new/page.tsx  -> post a listing form           - Côme
   src/app/login/page.tsx, src/app/signup/page.tsx                 - Andrea
   src/app/my-listings/page.tsx                                    - Leo
   src/components/        -> reusable pieces (ListingCard, FilterBar...)
   src/lib/types.ts       -> the shared Listing / User types (below)
   src/lib/mock-data.ts   -> fake listings to build the UI with
   src/app/api/...        -> backend routes (Taoufik only)
   prisma/                -> database schema (Taoufik only)

Tech: Next.js 16 (App Router) + TypeScript + Tailwind CSS.
You write React components in .tsx files and style with Tailwind
classes (className="rounded-lg bg-white p-4 shadow"). No CSS files
needed.


THE SHARED DATA SHAPE  (src/lib/types.ts — everyone codes against this)
-----------------------------------------------------------------------
   export type City = "Milan" | "Madrid" | "Geneva" | "Paris" | "Marseille";
   export type Currency = "EUR" | "CHF";

   export type Listing = {
     id: string;
     ownerId: string;
     ownerName: string;
     ownerEmail: string;
     city: City;
     neighbourhood: string;        // e.g. "Navigli", "Malasaña"
     rent: number;                 // per month
     currency: Currency;           // Geneva = CHF, others = EUR
     availableFrom: string;        // ISO date "2026-01-15"
     availableUntil: string | null;// null = open-ended
     rooms: number;                // 1 = studio
     description: string;
     photos: string[];             // image URLs (may be empty)
     status: "active" | "taken";
     createdAt: string;            // ISO date-time
   };

   export type User = {
     id: string;
     name: string;
     email: string;
   };

The data now comes from a real database (Neon Postgres). Two ways to
get it:

   Server components (pages):  import { getListings, getListing }
                               from "@/lib/listings"  and await them.
   Client components (forms):  fetch("/api/listings", ...) — routes,
                               filters and error format are in README.md.

While there is no login yet, add the header  x-user-id: u-1  to POST /
PUT / PATCH requests in development to act as a seeded user.
src/lib/mock-data.ts still exists: it is the seed data and is handy in
tests, but pages should not import it any more.


NEXT.JS THINGS THAT WILL BITE YOU (read now, thank me later)
-------------------------------------------------------------
- A file is a "server component" by default. If you use useState,
  onClick, useEffect, or any browser thing, put  "use client";  as the
  FIRST line of that file.
- Page files receive params/searchParams as PROMISES in Next 16:
     export default async function Page({ params }: { params: Promise<{ id: string }> }) {
       const { id } = await params;
     }
- If a client component uses useSearchParams(), wrap it in <Suspense>
  in the parent, or the build fails.
- Use <Link href="/..."> from "next/link" for internal links, not <a>.
- Use <Image> from "next/image" for photos (needs width/height or fill).
- Dates: format them in one helper (src/lib/format.ts) so every page
  shows dates the same way. Don't call new Date() inside JSX directly
  — it causes "hydration mismatch" warnings.


PROMPT-ENGINEERING TIPS (the actual point of the class)
-------------------------------------------------------
Good prompts to your AI assistant contain:
  1. Context:   "Next.js 16 App Router, TypeScript, Tailwind. Here is
                 the Listing type: <paste it>."
  2. The task:  "Create src/components/ListingCard.tsx that shows..."
  3. Constraints: "No external UI library. Must work on mobile.
                 Use next/image for the photo."
  4. Example:   paste one mock listing so it sees real data.
  5. Iterate:   "Now make the rent bigger and add the city as a badge."

Keep a file  tasks/prompts-<yourname>.md  where you paste the prompts
that worked (and the ones that didn't). It's part of your grade AND
it helps the next person.
